# 入力・設定・結果ファイル

更新日：2026-10-27。状態：現行仕様。

## 機体

Load Airframeは利用者が選択した`.ork`／`.ork.gz`を読み込みます。Airframe JSONの選択欄や隣接ファイルの自動検索はありません。
機体名・ファイル名に依存せず、テスト用機体を既定機として自動選択しません。
取得優先順位は **.ork → Kazamidori自動計算 → 手入力**。出典を保持し、取得・計算済みの項目は手入力より優先します。

形状・寸法・フィン枚数／形状／配置、質量・CGを取得または部品から推定し、CP未取得時は同じ空力面からMach 0のCPを計算します。
全体取込は対応する単段・一定直径の胴体・ノーズ・3〜8枚の対称フィン1組を対象とします。
多段、複数モータ、未対応形状などは理由を示して拒否し、推測で変換しません。
未知の部品等で質量・CGが計算できなければ空欄にし、Manual Configで補完するか、OpenRocketへ機体全体の上書き値を保存して読み直します。
不足値がある間はRunを許可せず、前機体の値で補いません。

フィンの自由輪郭はm単位で、翼根前縁(0,0)、後方x、外向きy。頂点・交差・翼根位置等を検証します。
Manual Configの編集はドラフトで、Apply時に検証・反映、Cancelで破棄します。入力途中の0や小数を自動整形しません。
Save airframeのJSON出力と内部のJSON解析APIは現行コードに残りますが、Load画面の入力対象には含めません。
これは全入力を復元するセッション保存と同義ではありません。

## モータ・パラシュート・空力

- モータの燃焼後質量・ノズル位置・放出遅延・Isp・推進剤密度はMotor Specificationsが扱う。推力履歴はLoad Thrust CurveでCSVを選択する。
- .orkのモータ型番から乾燥質量・推力を推測しない。取得できるマウント位置や放出遅延との優先順位を保持する。
- パラシュートのCd・面積は.orkから取得できれば優先する。複数ある場合は自動選択せず、専用設定を指定する。
- 開傘ラグと水平風速追従率は専用設定。OpenRocketのdeploydelayを無条件で開傘ラグへ変換しない。
- Cd曲線CSVはMachとCdの有限・非負値、点数、厳密昇順を検証する。動力／無動力の対象を区別する。
- 推力曲線は時間の厳密昇順・有限値・非負推力・正の全力積を検証する。

## 保存形式

| 形式 | 担当・保存範囲 |
| --- | --- |
| `config.json`、version=1 | 計算、モータ、傘、空力、練習風、モンブラン条件。起動時読込とメニュー操作 |
| 設定セッション、schema_version=1 | Cd・Cd曲線、モータIsp／密度、気象関連オプション、モンブラン条件。全機体・全結果の包括的復元ではない |
| 結果JSON、format=`kazamidori-results` | version=1、coordinates=`ENU_m`。公称・MC結果、文脈、UTCのexported_at、実行時入力スナップショット |
| 結果CSV／PNG | 軌道・着地点等の出力／描画。復元用JSONと用途を区別する |
| 予報CSV | UTC対象時刻、地点、高度／気圧面等を検証し、対象スナップショットを選択する |

結果にはrun_id、入力版、モデル版、依存版、乱数シードを持つ実行条件を保持します。
入力変更後の出力にも当時の条件を使い、現在の入力欄を実行条件として書き込みません。
結果JSONの読込は表示・文脈を復元する操作であり、飛行再実行・地図ダウンロード・ライブ監視の開始はしません。
保存は一時ファイルからの置換を使用します。セッション全体を検証してから適用し、後半の不正値で途中まで状態を変更しません。
主な実装：[機体解析](../utils/openrocket_airframe.py)、[設定](../utils/configuration.py)、[セッション](../utils/session_manager.py)、[結果](../utils/result_io.py)。

## 今後の拡張

観測生データ、正規化データ、予報出所、入力ファイルのハッシュ、測器校正、作成日時と実行条件を結び付けます。
推力曲線と乾燥質量を一緒に扱うモータ仕様形式も検討し、既存CSVとの識別・単位・優先順位を定義してから導入します。
復元範囲、外部ファイルの欠落・変更、未知スキーマ、最近使ったファイル、JST付き既定名を仕様化します。
Cd表編集はドラフトをまとめて検証し、プレビューのたびに飛行計算しません。
各形式を混同せず、保存失敗時の元データ保護と往復整合を確認します。
