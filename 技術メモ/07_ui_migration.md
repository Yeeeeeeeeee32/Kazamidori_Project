# UI移行方針

更新日：2026-10-27。状態：将来設計。React／QWebEngineView／QWebChannelは未組込。

## 目標と責務

Python Core＋PySide6 Desktop Shell＋React/TypeScriptを目標とします。初期段階で独立したFastAPIサーバーは設けません。
現在のWidgets／Matplotlibを維持しながら、同じPythonサービスへ接続する表示を段階的に試します。

| 領域 | 責務 |
| --- | --- |
| Python | RocketPy、探索、MC、統計、判定、入力検証、Koinobori通信 |
| PySide6 | ウィンドウ、ファイル操作、通知、Workerと終了管理 |
| QWebEngineView | 同梱したローカルReact画面 |
| React/TypeScript | 表示、編集ドラフト、操作要求 |
| QWebChannel | 型付き状態取得、要求、進捗、完了／失敗の橋渡し |

物理式とGO判定をフロントエンドへ複製しません。QWebChannel導入だけでCPU負荷・GIL・応答性が改善するとはみなしません。

## ブリッジの契約

版、request ID、入力スナップショット／版、更新順序、取消要求／完了を定義します。
SI単位、ENU、FROM風向、東基準反時計回り角度、JST表示／UTC内部時刻を明示します。
未取得・失敗・空配列を区別し、NaN／InfinityをJSON数値として送信しません。
古い応答を破棄し、大きな軌道・MC配列の間引き／差分／分割を測定します。

## 段階と確認

| 段階 | 内容 | 受入確認 |
| --- | --- | --- |
| M0 | 入力・結果・正常／失敗ケースを固定 | 単位と基準結果を追跡できる |
| M1 | PythonサービスとUIを分離 | 同じ条件で結果を再現する |
| M2 | 読み取り専用のReact PoC | 状態取得、型、例外、終了を確認する |
| M3 | 設定・進捗・風況を移行 | 入力反映、取消、更新遅延、JSTを確認する |
| M4 | 3D・地図・KDE・CEPを移行 | 座標、角度、縮尺、統計領域を比較する |
| M5 | 統合とWindows配布 | オフライン、切断、再起動、保存復元を確認する |

最初のPoCは物理・Worker・既存地図／3D・判定を変更しません。
実機統合と全画面置換を同時に行わず、回帰・配布検証後に現行UIを取り除くか判断します。
React・フォント・地図等は同梱し、実行時にCDNへ依存しません。予報の新規取得はオンライン機能として区別します。
Pythonブリッジは信頼するローカル画面だけに公開し、外部ページへ任意パス操作・コード実行を公開しません。
Qt WebEngineの実行ファイル・資産の同梱、終了処理も対象Windows PCで検証します。
