# 性能・並列化

更新日：2026-10-27。状態：MCはQThread内で逐次実行。並列化・JIT・独自積分器は未実装案。

## 測定から始める

固定入力・固定シードで公称計算、探索、MC、統計、描画を分けて計測します。
初回と定常時、試行数・完了／失敗件数・RSS・依存版・取消応答・風更新遅延を記録します。
結果を変えない重複構築・補間・転送を削減してから、独立試行の並列化を比較します。
RocketPyがNumPy／SciPy等を使うため、全処理が純Pythonであるとも、QThreadなら常にCPU並列実行できるとも断定しません。
`core/mc_worker.py`のチャンク関数やfreeze_supportの存在だけでプロセス並列が接続済みとは扱いません。

## プロセス並列化の設計要件

- Windowsのspawnを前提に、子プロセスからQtを読み込まない。
- スカラーだけでなく推力・高度別風・機体設定を渡す。初期化時共有、チャンク、転送量を比較する。
- 完了順によらない試行IDとシード、結果順序、失敗分類を保つ。
- 投入中ジョブ数とプロセス数を制限し、CPU数に加えメモリ・起動時間も評価する。
- 軌道全体のIPCを避け、必要な着地点・指標・失敗理由に絞る。
- 未開始ジョブの取消と実行中処理を区別し、古い結果を破棄する。Future.cancelだけで実行中の積分を停止できるとは扱わない。
- Python 3.10で使えるAPIを基準とし、新しいPython専用の引数を無条件で使わない。

## メモリと数値計算

N試行の着地点はO(N)、代表軌道T点はO(T)、G×GのKDE格子はO(G²)。並列化は各Flightのメモリも加算します。
delによる参照削除はRSSの即時返却を保証しません。平均・分散の逐次集計と、散布図・KDEに必要な全点保持を区別します。
Numba等は対応する数値関数で効果を計測し、RocketPy全体へデコレータを付ければ高速になるとは扱いません。
固定刻みRK4、fastmath、粗い刻み、C++化はイベント検出・質量変化・誤差制御の再検証を伴います。

## 受入確認

逐次版と同じ入力群で高度・着地・開傘時刻・失敗分類を比較し、実装前に決めた許容差内であることを確認します。
速度・メモリ・起動・取消・連続実行・UI応答・Windows配布を測定し、改善がない変更は採用しません。
