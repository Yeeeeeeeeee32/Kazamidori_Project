## 2025-02-24 - Parallelized grid search optimizations with ProcessPoolExecutor IPC Memory Overheads
**Learning:** For Phase 1 Grid Search (`optimize_launch_angle`), evaluations are embarrassingly parallel. However, returning the full `simulate_once` result dictionaries containing large RocketPy trajectory arrays (numpy arrays) via `ProcessPoolExecutor` inter-process communication (IPC) creates massive serialization/deserialization overhead that can negate the multiprocessing speedup and cause memory bloat.
**Action:** When parallelizing grid searches or Monte Carlo loops, always strip out large arrays in a module-level wrapper function (e.g., `_grid_search_worker`) and return only the necessary scalar metrics (apogee, impact position, success flag) needed to evaluate the objective score. Run one final sequential simulation at the end using the winning parameters to retrieve the full trajectory arrays.
