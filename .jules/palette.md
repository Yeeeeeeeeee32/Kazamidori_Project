## 2024-05-18 - PySide6 Explicit Dialog Actions vs Native Roles
**Learning:** In PySide6 applications, replacing standard 'Close' buttons with 'Apply' + 'Cancel' can cause functional regressions. A `QDialogButtonBox.Apply` button has an `ApplyRole` natively and will *not* trigger the `accepted` signal unless explicitly wired to a custom save state, meaning developers cannot simply swap it out and expect standard `accept()` behavior. Additionally, if the dialog already features explicit save functions (like "Save JSON"), adding an "Apply" button introduces confusing redundancy.
**Action:** When adding explicit 'Apply' / 'OK' buttons in PySide6 dialogs to improve UX, ensure they are instantiated with the `AcceptRole` or manually wired to commit data before `accept()`. Avoid adding them if the view already provides context-specific save actions. Ensure to keep visual cue safety nets (like `border: 1px solid red`) on `editingFinished` to support keyboard navigation validation.
